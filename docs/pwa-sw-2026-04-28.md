# PWA / Service Worker 実装メモ — 2026-04-28

inryokü サイトに Service Worker + PWA を導入。
オフライン耐性を獲得しつつ、既存動作を破壊しない。
"the connection is grey" — 接続が落ちても、世界はまだそこにある。

---

## 成果物

| ファイル | 役割 |
|---|---|
| `/sw.js` | Service Worker 本体（cache-first / network-first / SWR） |
| `/offline.html` | オフライン fallback（grey 美学、3.3 KB） |
| `/register.js` | SW 登録 + PWA インストール促進（update toast / install banner / iOS hint） |

`index.html` / `p3_test.html` の `<body>` 末尾に
`<script src="register.js?v=20260428" defer></script>` を追加。

## キャッシュ戦略

cache name: **`inryoku-v1-2026-04-28`**（4 つに分割）

```
inryoku-v1-2026-04-28-static   静的アセット（vendor / css / js / fonts）
inryoku-v1-2026-04-28-html     HTML ドキュメント
inryoku-v1-2026-04-28-api      /api/* レスポンス
inryoku-v1-2026-04-28-image    *.png / *.jpg / *.webp / *.svg / *.glb / *.mp3
```

| 種類 | 戦略 | 備考 |
|---|---|---|
| 静的アセット (`/vendor/*`, `*.css`, `*.js`, `/particle_*.{js,css}`, fonts) | **cache-first** | 1 度取れば次回は瞬時 |
| 画像 (`/public/*`, `*.png` 等) | **cache-first** | 同上、別キャッシュで容量管理 |
| HTML | **stale-while-revalidate** | 即座に表示 → 裏で更新 |
| `/api/*` | **network-first (5s timeout)** | 失敗時は cache → JSON `{error:"offline", message:"the connection is grey"}` |
| 完全 fallback | `offline.html` | HTML がネットも cache も無いとき |

### 除外（キャッシュしない）

- `/grey/*`（動的 user content）
- `/api/subscribers`（admin endpoint の実体）
- `/api/subscribe`, `/api/checkout`, `/api/gelato`, `/api/chat`, `/api/contact`, `/api/ref/`, `/api/grey/`
- `GET` 以外（`POST` 等は素通し）
- 異なる origin（Shopify CDN / Groq / qrserver 等）は素通し

### Precache（install 時）

最小コアのみ — install を高速・確実に：

```
/, /offline.html, /manifest.json,
/inryoku_logo_icon.png,
/p3_styles.css, /particle_glyphs.css, /particle_rings.css,
/vendor/three.min.js
```

個別 `cache.add` で wrap し、1 個失敗しても install は続行。

## ライフサイクル

- **install**: precache。`skipWaiting()` は `register.js` から `postMessage` で明示制御。
- **activate**: `ALL_CACHES` に含まれない旧キャッシュを `caches.delete`、`clients.claim()`。
- **message**:
  - `SKIP_WAITING` → `self.skipWaiting()`
  - `CLEAR_CACHES` → 全 cache 削除（デバッグ用）
- **sync** (Background Sync API):
  - tag `inryoku-retry-subscribe` のみ受け付け（現状 placeholder / no-op）

---

## クライアント側 (`register.js`)

- `'serviceWorker' in navigator` を確認後に `register('/sw.js', { scope: '/' })`。
- `file://` 等の非 http(s) 環境では登録しない。
- `load` 後に登録 → critical path を邪魔しない。
- 1 時間ごとに `registration.update()`。
- `updatefound` で新 SW を検知したら **update toast**（grey、控えめ）を表示し、
  ユーザが `reload` を押した時のみ `SKIP_WAITING` → `controllerchange` でリロード。

### PWA インストール促進

- `beforeinstallprompt` を `preventDefault()` で保持。
- 30 秒後に控えめな install banner（「install inryokü / add」）。
- `appinstalled` で banner を消し dismiss を記録。
- iOS（`beforeinstallprompt` 非対応）は 45 秒後に
  「add to home screen: tap **share** → **add to home screen**」のヒントを表示。
- どちらも一度 `×` で閉じれば `localStorage` で **7 日間** 再表示しない。

### 公開 API（`window.inryokuPWA`）

```js
window.inryokuPWA.registration   // ServiceWorkerRegistration
window.inryokuPWA.requestSync(tag) -> Promise<bool>
window.inryokuPWA.isStandalone()
window.inryokuPWA.isIOS()
```

## オフラインページ (`offline.html`)

- 3.3 KB（5 KB 上限内）。external 依存ゼロ。
- 中央に **breathing grey orb**（radial gradient + scale animation, 4.6s）。
- コピー:
  - `the connection is grey`
  - 「接続が途切れています。でも、グレーは欠落ではありません。」
  - `Networks fail. Signals fade. The world is still here, just unobserved.`
  - `— observe, and the 50% becomes 101%.`
- アクション: `retry` / `return to inryokü`
- `online` イベント検知 → retry ボタンが `reconnect` に変化。
- `prefers-reduced-motion: reduce` で animation 停止。

## 既存動作との非破壊性

- 触ってない: `server.js`, `p3_code_for_claude.js`, `p3_styles.css`,
  `particle_*.*`, `enhance.js`。
- `index.html` / `p3_test.html` は `</body>` 直前に 1 行追加のみ。
- `register.js` は IIFE、global は `window.inryokuPWA` のみ。
- 失敗は `console.warn` で握り、UX を止めない。
- `POST` / cross-origin / 除外 path は完全素通し → API 機能・CSP 違反ゼロ。

### CSP 確認（security-fixes-2026-04-28.md）

`server.js` の `CSP_HTML` は `default-src 'self'` を含む。
`worker-src` 個別宣言は無いが、Service Worker は CSP 上 `default-src` に
fallback するため、同 origin の `/sw.js` は許可される。

## 検証

```
node --check sw.js        # OK
node --check register.js  # OK
wc -c offline.html        # 3283 (< 5120)
```

DevTools での確認手順:

1. `Application > Service Workers` に `sw.js (activated and running)` が出る
2. `Application > Cache Storage` に 4 つの cache（最低 `-static` と `-html`）
3. `Network > Offline` でリロード → `offline.html` または cache 済み HTML
4. `Application > Manifest` で installable 判定 ✓
5. update 反映: `sw.js` の `VERSION` を上げて push → toast 表示
   → `reload` クリック → 自動リロードで新版

## 既知の限界 / 今後

- Background Sync の payload 永続化層（IndexedDB）は未実装。
  カート復元 / subscribe リトライは `register.js` の `requestSync(tag)` 経由で
  予約はできるが、SW 側 handler は no-op。実データ層を持つフェーズで実装。
- iOS は `beforeinstallprompt` 非対応のため、UX は文字案内のみ。
- 画像 cache に LRU は無い。容量肥大したら `caches.delete` 戦略を入れる。
